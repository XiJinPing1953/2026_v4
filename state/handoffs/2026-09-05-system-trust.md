## 已实现的业务行为

账务：销售、客户结算及导出、首页销售指标、催收销售应收使用同一金额源码。明确 sale 按单计费，customer_flow 不重复形成销售应收；缺失 m³ 模式返回待核并停止相关账务写入。详情保留源单可读；前端不把 null 显示成可信零，缓存切换恢复相应提示；销售导出拒绝缺页、重复页和总数变化。

完整读取：计算使用 `_id` 游标、前后计数和读取期间创建/修改检测；超过上限明确未完成。返回规则版本与读取时点，明确非原子快照。不能检测所有跨集合并发，也不能据此证明不同请求看到了同一时点。

历史核查：`getLegacyM3EvidenceV1` 是超管只读原始资料入口，绕开金额重算，按客户提供期间 m³ 源单及该客户所有期间/状态流量结算；每集合超过 5,000 条明确拒绝。采集默认使用该入口双读；旧部署需显式 `--legacy-projection`，不能静默降级成同等证据。报告只给关联和候选，不自动确认覆盖。

逐单分类：`crm-sale.classifyLegacyM3SettlementV1` 限超管，要求 id、sale/customer_flow、至少 8 字依据、expected_source_version、`CLASSIFY_M3_SETTLEMENT`。条件更新检查模式与版本，源单保存依据/操作者/时间/规则版本；余额刷新失败返回 207。相同归属重试只重做刷新，不能重写已确认归属。接口未上线、无批量分类执行，尚无专用页面。

灌装：新批量和单条/PDA 保存进入同一持久操作；源单/流转/库存短事务、日期/瓶号占位、冻结版本、分段异常扫描、租约、退避重试、后台调度与前端状态查询已接入。监管入队保留在单条链路，后台读取当前授权 token，不把 token 持久化到任务。对历史无占位的记录也在事务内查重。旧事件完整内容哈希变化使扫描游标失效。

发布：公共规则副本/ACL/本地依赖、根 schema 与兼容副本检查进入 `npm test`。产品分别版本化；已提交源码、产物哈希、目标空间、函数/数据库显式范围写候选清单。网页发布后核对所有静态文件；候选清单保持不变，发布结果另存回执。禁止将 init_data 混入数据库变更清单。

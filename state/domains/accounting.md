# 账务当前决定

适用：销售金额、客户结算、管理汇总及导出。当前目标与实际交付状态见 [STATE](../../STATE.md)，凭证入口见 [ACCOUNTING](../../docs/ACCOUNTING.md)。

## A-01：结算归属明确后才计算（2026-09-05）

来源：用户批准的“数据可信与反复返工”改造计划；历史业务迁移见旧 STATE `2026-03-27 客户对账页承接 m3 计费`。本决定替代“看到 m3 就把所有旧销售归零”以及“缺少模式就当普通销售”的两种推断。

- 新建 m³ 客户销售默认 `settlement_mode=customer_flow`：销售只记录重量/流转，流量结算单形成应收。
- 已存单据明确为 `customer_flow` 时，销售应收为零；明确为 `sale` 时按该单计费，包括明确归属的历史 m³ 销售。
- 旧 m³ 单据缺失或无效模式时，详情仍可读取并显示金额为待核（null），账务合计、导出和涉及账务的变更返回 `FINANCIAL_CLASSIFICATION_REQUIRED`（409）及待核源单，不能选择 0 或气量乘价作为确定值。
- 逐笔核查客户、期间、流量结算与来源关联；只因同客户、同期间或金额相近不能认定覆盖。没有可靠对应证据的单据保持待核，不自动修账。
- 权威后端模块为 [saleAccounting.js](../../uniCloud-alipay/cloudfunctions/common/saleAccounting.js)；销售/结算及导出使用相同规则及版本，部署副本由统一同步工具管理。代码合入、测试、线上状态分开记录。

## A-02：营收、应收和现金不能互相代替（2026-05-15，2026-09-05确认）

来源：旧 STATE `2026-05-15 累计营收保留历史销售抹零前金额`、`累计营收/实收排除期初历史欠款`，以及本轮批准计划；替代早期把期初、抹零和净应收混入本期营收的汇总口径。

- 营收使用明确归属的销售/流量及本期其他费用来源；期初历史欠款参与余额，但不算本期营收或本期实收。
- 有效应收表达扣除抹零等后的债权；现金收款、非现金冲抵、退款、未分配预收和期初余额分别展示、可追溯到来源。
- 退款保留负号；冲抵和抹零不冒充现金。销售自身实收与客户收款分配不能重复计入。
- 整车优先使用出厂毛重减回厂毛重和已明确的结算称重；代理销售按关联代理灌装，不伪装成普通瓶销售。
- 修改统计或导出时保留来源类型、来源 ID、业务日期、规则版本和计算完整性。累计与期间指标使用相同字段定义，不能只比较总金额。

## A-03：核对是带读取时间的证据（2026-09-05）

来源：批准计划；新增，替代把多次独立查询称为同一数据库快照的做法。

完整性由后端 [financialRead.js](../../uniCloud-alipay/cloudfunctions/common/financialRead.js) 管理；取数上限、超时或无法证明完整时不得返回确定总计。核对报告保存开始/结束时点及期间内可检测的变更；检测能力不足时说明限制。历史报告“32 笔、91,612.92 元”只作为复核线索，原始 JSON 未保留，本轮重新只读核查得到 60 张 m³ 销售、38 张缺模式待核、9 张流量结算投影；旧接口缺关联证据，仍不能作为自动修账依据。详见本轮交接。

## A-04：历史分类与审计通道（2026-09-06）

缺失归属不会阻断超管的原始取证入口 `crm-customer-settlement.getLegacyM3EvidenceV1`。它按客户和销售期间完整读取原始销售，并保留该客户全部期间的流量单；不先计算应收。采集工具双读仍明确非原子快照。

归属确认后使用 `crm-sale.classifyLegacyM3SettlementV1` 单独修改模式，必须提供来源依据及预期源版本；保留审计字段。余额刷新失败明确返回 207，重试可继续刷新。不得通过普通编辑默认值修复历史分类。09-06 时尚未执行分类；09-07 指定客户的证据确认、分类及关联账务修正已完成，见 A-05。其他客户未重核；全量账务候选版上线前仍须处理待核保护对旧单的影响。

## A-05：已确认停用客户的流量与收款修正（2026-09-07）

来源：用户提供完整表数、会计收款截图，确认跨期对应关系，并明确授权修正该客户使账目与会计相符。只适用于本次已确认客户；替代 A-04 中该客户“尚未分类/未写入”的执行状态，不改变其他客户的待核要求。

- 表格用气量为下一次表数减本次表数；保留四位气量和既有 m³ 金额三位截取规则。送气日期与抄表边界分开保留；确认的历史表底修正须有前后值及来源校验值。
- 保留 37 张送气单及出回瓶、押金等运营事实；34 张缺模式单以证据明确归为 customer_flow，由 4 张连续流量结算形成应收，原销售内嵌收款迁移到实际收款及分配关系，避免双计。
- 跨年欠款单列期初，本年气款按抄表区间结算；会计与流量精度产生的小额结算尾差单列其他费用并注明原因，不改气量凑账。实际收款日期不等同用气归属期间。
- 3 笔实际收款以会计证据为准；未知渠道保存 unknown 并显示“渠道待核”，不得默认现金或银行。原合并收款与分配保留作废及原值记录。
- 已量化金额以整数最小单位累加与相减，避免浮点误差再次截掉 0.001；客户汇总、明细导出、会计账簿导出须一致。
- 专用修正入口限定超管和该客户，先留完整备份及固定计划哈希，再事务核对源版本后执行；同一 run_id 重试返回已完成。不得把这一专用方案直接用于其他客户。

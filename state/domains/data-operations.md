# 数据导入与修正

本分支边界：灌装持久处理、PDA冻结完成及恢复导入属于 `codex/system-trust-foundation` 的未发布候选；main保留既有业务实现，以下候选决定用于后续验收。
适用：云数据导入、历史改单、清理和重建。来源：原项目技能导入流程，2026-09-05 收敛到仓库维护；替代技能内复制的状态协议和命令大全。授权沿用当前会话，不额外发明确认流程。

1. 固定 provider、space-id、源文件和目标范围；读取脚本参数和当前实现，不能把历史命令当可直接重放的任务。
2. 检查源内重复、目标冲突、缺失字段和匹配键，输出预览。增量操作按明确键 update/upsert，修复不得绕过领域源单接口只改投影。
3. 对可能改写历史的操作保留受影响原值或可恢复 run_id。按已批准范围执行，再核对源单、关联记录及业务合计。
4. 报告包含读取/执行时点、payload、matched、updated/unchanged、missing、rejected、失败原因；匹配但无需更新不能误报为失败，也不能把 missing 隐去。
5. 原始和清洗数据放受控本地输出目录，不默认提交 `docs/`。仓库只存必要脱敏摘要和校验，发布清单不包含客户明细或凭据。

`cloud functions --initdatabase` 不用于普通修复；凭证、流转等修正使用对应明确接口。范围超出已有授权或历史账务归属无法确认时才提出实际未决问题。结果写 [交接](../handoffs/TEMPLATE.md)，更新 [STATE](../../STATE.md)，不追加流水账。

## D-01：历史灌装导入按原操作恢复（2026-09-09，候选未发布）

来源：主线导入补口及总验收，替代旧导入把code0计作新增成功的逻辑。源记录身份生成稳定编号，规范化内容在发送前写入本地恢复日志；同一input/report重跑沿用原编号，实质变化报冲突。后台须具备v2、源单回查和内容摘要能力；回查内容摘要及源版本匹配后才计保存成功，后续完成另计。

重跑遇已有pending/processing/failed操作时经原retry接口恢复，再回读确认，不能仅查询failed后永远等待；内容或版本不匹配则停止重放。预览零业务写入，已有精确匹配单据仍跳过，不隐式更新。一个报告只由一个进程执行；不把旧报告success_total追溯解释为已回读保存。原始恢复日志不入库。9项专属验证含真实导入→灌装入口及重试回包丢失；尚未执行任何真实云导入，见[总验收](../handoffs/2026-09-09-mainline-entry-acceptance.md)。

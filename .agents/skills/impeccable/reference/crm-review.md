# 2026_v4 页面审查约定

这是已运行的中文能源 CRM，目标是让工作人员快速看清数字、核对源单、处理待核事项。采用 Impeccable 的 Operate 模式。当前只审查页面；不能因为“美化”改变业务定义或推出新版。

## 权威来源

- [工程规则](../../../../docs/RULES.md)、[当前状态](../../../../STATE.md)、[领域索引](../../../../state/INDEX.md)。复用已读且未变化的资料，不每次全量加载。
- uni-app Vue 3 + Vite，支付宝 uniCloud。薄页面只编排；交互状态由 composables 管理；权威计算、完整取数和权限在后端。
- [现有色彩/间距/字号/圆角 token](../../../../src/uni.scss) 与 [基础组件](../../../../src/components/base/) 是既有视觉依据。保留商务蓝白、中文系统字体及语义状态色，不因为上游审美偏好更换字体、颜色、框架或加入动画。
- 优先参考 AppPage、AppSection、AppFilterBar、AppTable、AppTag、AppDatePresetBar。复用不等于无条件采用：检查键盘、焦点和当前平台的实际渲染。

## 审查重点

- 检查 pages.json 原生导航与 AppPage 是否重复；标题、筛选、正文和操作是否同轴。针对页面提出最小修改建议，不顺手重排全站。
- 首屏让用户找到本页主要工作入口。大量业务记录优先紧凑、可比较；详情按需展开，手机保留可点按的卡片。不要用装饰大卡片挤压核查区域。
- 数值、单位、范围、数据时点及待核原因靠近对应内容。缺失用“—/待核”，不能为了简洁显示0或移除必要风险信息。
- 检查空结果、读取中、上次结果过期、权限不足和展开态。自动刷新不应把正在阅读的详情反复清空或造成跳动。
- 区分 H5 桌面、窄屏、PDA/小程序。uni-app 的 view/text/rpx 不直接等同原生 HTML；代码断点与扫描结果不构成真机验收。浏览器使用当前可用的官方控制工具，不注入审查脚本，不向外部服务发送 CRM 明细。

## 天然气闭环的固定口径

审查对象：[GasClosureView.vue](../../../../src/components/domain/gas/GasClosureView.vue)、[useGasClosure.js](../../../../src/composables/gas/useGasClosure.js)、[路由](../../../../src/pages/gas-closure/index.vue)。业务依据见[闭环交接](../../../../state/handoffs/2026-10-10-gas-closure-module.md)。

首次灌装日与观察截止日不同；同周期跨日补灌合并，出售只计一次。累计灌入、已核出瓶、未出瓶末次账面瓶内重、待核灌入不是可以随意相减的同口径余额。已核代表来源链可解释，不代表无损耗；末次账面瓶内重不是当前实测库存。

每日灌前大罐余量独立于瓶号/状态筛选，是带时间、液位、压力和缺口提示的仪表候选。不能为了界面简洁去掉“待现场核准”，不能将疑似下降时间写作真实开阀时间。逐车成本、混罐和利润仍未完成。UI建议保留上述边界、源单跳转和60秒刷新能力。

报告以截图及代码可证明的问题为主。自动检测0条也可以有明确视觉问题；检测告警须经核实，不能直接把通用网页规则当作 uni-app 缺陷。记录未实测项即可，不为凑分数或清零告警扩展工作。

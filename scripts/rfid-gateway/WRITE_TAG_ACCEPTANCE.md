# RFID 写标验收清单

本清单用于第一轮门口盘点验收：先写 1 个车辆标签和 2 个瓶子标签，再确认 ECS 网关能输出车辆盘点会话。

## 本轮测试标签

| 用途 | 内部序列号 | 写入 EPC |
| --- | ---: | --- |
| 车辆测试标签 | 1 | `585401020000000000011FA3` |
| 瓶子测试标签 A | 135 | `58540101000000000087AD01` |
| 瓶子测试标签 B | 5000 | `58540101000000001388E035` |

也可以用脚本重新生成或校验：

```bash
node scripts/rfid-gateway/issue-tags.cjs
node scripts/rfid-gateway/issue-tags.cjs --validate 585401020000000000011FA3
```

## 写标前检查

- 桌面 UHF Demo 工具能连接本地读写器。
- 每次写标时，读写器附近只放一个待写标签。
- 先读一次标签，确认列表里只有一个 EPC。
- 本轮不写车牌、瓶号明文，只写上表 EPC；车牌/瓶号和 EPC 的绑定后续进云端。

## UHF Demo 写 EPC

1. 进入标签测试/标签读写页面，点击读标签，确认只读到一个标签。
2. 进入 EPC 写入功能。
3. 如果工具要求选择存储区，选择 `EPC` 区。
4. 如果工具要求填写起始地址，选择从 EPC 内容区开始写；常见工具为 `word address = 2`。
5. 如果工具要求填写长度，12 字节 EPC 对应 `6 words`。
6. 如果工具要求访问密码，默认先用 `00000000`。
7. 写入上表 EPC，写完立即重新读标签。
8. 读回 EPC 必须与写入值完全一致，再贴标签或进入下一张标签。

如果写入失败，先降低同时在场标签数量、缩短标签距离，并确认该标签支持改写 EPC。

## 门口盘点验收

在 ECS 上打开日志：

```bash
journalctl -u xt-rfid-gateway -f
```

现场验收顺序：

1. 让车辆测试标签进入读写器范围。
2. 观察日志出现 `rfid_tag_seen`，并且 `entity_type` 为 `vehicle`。
3. 在 15 秒窗口内放入两个瓶子测试标签。
4. 观察瓶子日志 `entity_type` 为 `bottle`。
5. 等待 15 秒窗口结束，观察 `rfid_session_summary`。

验收成功的关键字段：

```text
vehicle_epc = 585401020000000000011FA3
bottle_total = 2
bottles 包含 58540101000000000087AD01 和 58540101000000001388E035
vehicle_conflict = false
```

## 异常判断

- 出厂 EPC 会显示 `unknown_epc`，这不是网关错误，表示该标签还没写入 XT EPC。
- 如果只看到瓶子、没有 summary，通常是没有先读到车辆标签，或车辆标签没有写成 `entity_type=vehicle`。
- 如果 `vehicle_conflict=true`，表示同一个窗口读到了多个车辆标签；验收时应只保留一个车辆测试标签在场。
- 如果 `bottle_total` 少于实际数量，先把读写器功率从 16-18 dBm 往上小幅调整，再复测。

# 充装许可网关 V1 - MCGS/PLC 接入与安全设计说明

> 适用对象：负责正式触摸屏组态和 PLC 程序的工程师
> 设备：TPC7022Ei + McgsPro 3.5.1.6963 + S7-200 SMART ST20
> 交接日期：2026-07-20
> 附件分工：Windows 网关安装程序和当前 MCGS 测试工程由项目负责人另行发送；本文件负责解释配置、接口、脚本、安全设计和验证依据。
> 安全原则：任何通信异常、响应不匹配、云端故障或程序异常均默认禁止充装。

## 1. 接收工程师先看这一页

Windows 网关和 MCGS 测试工程已经在真实 TPC7022Ei 上完成通信和故障关闭验证。当前测试工程的作用是提供一份可运行的参考实现，不要求正式充装画面照搬测试页面。

正式 HMI 可以只显示瓶号、查询按钮和一个“是否允许充装”标签；Boot ID、序号、状态码、位图和心跳等内容可以放在维护诊断页。但内部协议和安全判断不能因画面简化而删除。

当前测试工程最终生成的核心变量是：

```text
GatewayPermitOk
```

- `GatewayPermitOk=1`：当前瓶号、当前网关启动周期和当前请求序号完整匹配，云端返回允许，网关无故障，心跳有效，而且不存在任何失败明细。
- `GatewayPermitOk=0`：禁止充装。处理中、编辑瓶号、网关断线、云端故障、响应过期或任何条件不完整时均保持 0。
- 正式 HMI 可以把它关联到“网关查询许可”标签，也可以作为 HMI 写给 PLC 的许可来源。
- 如果正式画面要显示“设备最终允许充装”，应显示 PLC 计算后的最终许可，而不是只显示网关查询结果。

> 不得把 `RS03`（原始许可位）直接关联 PLC 或充装流程。`RS03` 只是云端结果的一部分；缺少 Boot ID、请求序号、心跳、网关状态、故障码和需重查判断时，可能把旧结果误认为当前结果。

## 2. 数据链路和职责边界

```text
操作员输入瓶号
    ↓
TPC7022Ei / MCGS
    ↓  Modbus TCP：提交瓶号、Boot ID、请求序号
Windows 充装许可网关
    ↓  HTTPS：查询气瓶并写云端审计
云函数 / 气瓶库 / 审计库
    ↓  允许、禁止原因、状态、心跳
Windows 网关
    ↓  Modbus TCP
MCGS 生成 GatewayPermitOk
    ├─→ 正式 HMI 状态标签
    └─→ 由负责 HMI/PLC 的工程师映射到 PLC
```

项目负责人提供：

- Windows 网关安装程序。
- 当前 MCGS 测试工程或工程备份。
- 网关登录所需的现场口令，通过安全方式另行提供。

接收工程师负责：

- 在正式 HMI 工程中复用或等价实现本文件的 Modbus 变量和两个脚本。
- 根据正式画面决定只显示一个许可标签，还是保留维护诊断页。
- 分配 HMI 到 PLC 的实际地址并完成 SMART200 通道。
- 在 PLC 内生成最终许可，并把它串联到原有充装条件；不得绕过急停、压力、阀门或设备原有保护。

### 3.3 配置步骤

1. 在 Windows 网关电脑上安装正式 x64 安装包。
2. 启动“新拓充装许可网关”，填写云函数URL和唯一网关ID；“专网监听IP”选择Windows电脑上实际用于与TPC通信的网卡地址。
3. Modbus端口填写`502`、Unit ID填写`1`；如现场确需修改，必须同步修改McgsPro设备配置。
4. 云端超时、心跳和补传周期保持已验证值`5000 ms`、`1000 ms`和`30000 ms`。
5. 点击“保存设置”。如端口或监听IP被修改，需要重新启动网关服务使监听配置完全生效。
6. 在“独立网关凭据”中输入现场明文网关口令，勾选“保存到系统安全凭据库”，点击“登录”。界面应显示密码已由Electron `safeStorage`保存，配置文件中不得出现明文密码。
7. 启动网关后确认：协议版本为1、Boot ID非零、网关状态为2、故障码为0、心跳每秒递增。
8. 需要开机运行时勾选“Windows登录后自动启动”。该功能已完成实机重启验证。

不得把云端密码哈希或令牌密钥填写到网关、HMI 或 PLC。Windows 网关输入的是另行提供的明文网关口令。

### 3.4 与网关有关的网络约束

- 本资料不规定TPC或Windows电脑使用哪个IP，也不重复说明现场组网和工程下载方法。
- 网关“专网监听IP”和McgsPro设备“远程IP”必须指向同一个Windows网卡地址。
- 网关监听端口与McgsPro远程端口必须一致，默认均为`502`；Unit ID与Modbus设备地址必须一致，默认均为`1`。
- Windows防火墙应把网关TCP端口的访问范围限制在现场HMI等必要设备；TCP 502不得暴露到互联网或不受控网络。
- 修改监听IP、端口或Unit ID后，应同步更新网关和McgsPro配置，并重新执行通信及断线测试。

## 5. 32个 Modbus TCP 保持寄存器

网关使用 PDU 0 基地址；McgsPro 使用从 `4WUB0001` 开始的 1 基通道。FC03 用于读取，FC06/FC16 用于写入。

{{REGISTER_TABLE}}

写入顺序不能修改：先写瓶号长度、16个字符字和请求 Boot ID；等待两个 200ms 循环周期；最后单独修改请求序号 `RQ01`。网关以新的非零请求序号作为提交标志，并在接收后立即把许可清零。响应字段全部写完后，网关最后更新 `RS01`，将其作为响应完成标志。

## 6. “提交查询”按钮脚本及安全考虑

{{SUBMIT_SCRIPT_BODY}}

### 6.1 为什么必须这样写

| 脚本设计 | 防止的风险 | 失效时的结果 |
|---|---|---|
| 只在 `SubmitStage=0` 时接受按钮 | 连续点击造成并发请求、序号覆盖或瓶号混合 | 忙时不启动第二个请求 |
| 提交开始立即置 `PermitNeedsRequery=1`、`GatewayPermitOk=0` | 新瓶号查询期间继续沿用上一瓶的允许结果 | 新查询一开始即禁止 |
| 瓶号长度限制为1至16 | 空瓶号、越界字符串或协议字段溢出 | 无效输入不会提交，许可保持0 |
| 写字符前将 `RQ03-RQ18` 全部清零 | 短瓶号继承上一长瓶号末尾字符 | 未使用字符固定为0 |
| 将 `BottleInput` 保存到 `SubmittedBottle` | 查询期间输入框被再次编辑，长度和字符来自不同瓶号 | 循环脚本发现变化后立即失效 |
| `RQ00=GW02` | 网关重启后旧请求被新启动周期误认 | Boot ID变化后旧请求无效 |
| 请求序号递增、跳过0并处理65535回绕 | 重复序号无法区分新旧请求 | 每次提交都有新的非零标识 |
| 先进入阶段1，等待两个200ms周期 | 驱动尚未写完长度和字符就提交序号 | 先让数据稳定，再提交 |
| `RQ01` 最后写入 | 网关读到一半新数据、一半旧数据 | 序号成为近似原子提交标志 |

核心原则：按钮脚本只负责准备一份完整、可识别、不会与旧请求混淆的数据快照；它不直接产生允许结果。

## 7. `PermitCycle200ms` 全局循环脚本及安全考虑

{{CYCLE_SCRIPT_BODY}}

### 7.1 为什么必须这样写

| 脚本设计 | 防止的风险 | 失效时的结果 |
|---|---|---|
| 输入框与 `SubmittedBottle` 不一致即清零 | 操作员看到旧瓶允许后改成另一个瓶号 | 编辑后立即禁止，必须重新查询 |
| 以“心跳是否变化”判断通讯，不判断是否大于0 | 心跳65535回绕到0被误判，或静态旧值被认为在线 | 连续3秒不变化即禁止 |
| 阶段1等待两周期后才写 `RQ01` | Modbus多寄存器写入未稳定 | 不会提前提交不完整请求 |
| 阶段2只接受 Boot ID和请求序号都匹配的终态响应 | 上一次请求的旧响应提前清除“需重查” | 旧响应不能恢复许可 |
| 40个周期仍无终态响应即超时 | 云端或网关卡住后HMI永久等待 | 约8秒后回到禁止和空闲状态 |
| 协议版本、网关状态和故障码每周期检查 | 网关降级、故障或协议不兼容时仍沿用许可 | 任一异常立即清零 |
| `RQ00`必须等于当前`GW02` | 网关重启后旧请求仍留在HMI寄存器中 | Boot ID变化立即要求重新查询 |
| 每个周期先执行 `GatewayPermitOk=0` | 条件曾经成立后许可被错误锁存 | 只有本周期全部条件成立才重新置1 |
| 允许必须同时满足`RS02=2、RS03=1、RS04/05/06=0` | 状态、原始位、主原因或明细相互矛盾 | 有任何失败信息都禁止 |
| 通讯恢复只到“需重查”状态 | 断线前的旧允许在恢复连接后自动回来 | 必须提交一次新查询才能重新允许 |

核心原则：`GatewayPermitOk`不是被某个事件“置位后保持”的许可，而是每200ms重新证明一次。只要本周期无法完整证明安全，它就是0。

## 10. 为安全考虑完成的测试，以及为什么要这样测试

| 已完成测试 | 观察结果 | 为什么必须测试 |
|---|---|---|
| HMI与Windows连通、TCP 502正常 | 协议1、Boot ID非零、状态2、故障0、心跳递增 | 先排除IP、端口、Unit ID和地址偏移错误；寄存器读到数值不代表读对了地址 |
| 正常允许查询 | `RS02=2、RS03=1、RS04/05/06=0`，许可为1 | 证明从瓶号编码、云端判定、审计写入到HMI匹配的完整成功链路 |
| `Y014`业务禁止 | 原因20、原始许可0、最终许可0 | 证明业务禁止不会因通信正常而被误当成允许，并验证原因码显示 |
| 只编辑瓶号、不提交 | `GatewayPermitOk`立即从1变0 | 防止上一瓶允许结果被新瓶号沿用，这是扫码或人工改号时最直接的交叉瓶风险 |
| 停止Windows网关 | 3秒内从允许转为通讯失效和许可0 | 验证心跳看门狗，而不是依赖TCP连接外观或静态旧寄存器值 |
| 重启Windows网关 | Boot ID改变，旧许可不恢复；重新查询后才允许 | 验证启动周期隔离，防止重启前响应被重启后的系统误用 |
| 断开云端网络 | Modbus心跳仍在，但新请求返回系统禁止90，许可0 | 验证“网关在线”不等于“云端判定成功”；网络故障必须故障关闭 |
| 恢复云端网络 | 旧许可不恢复；系统禁止审计补传；重查后才允许 | 验证恢复过程不会自动放行，并验证故障期间审计记录不会丢失 |
| 拔HMI-网关网线 | 3秒内清零；恢复只到需重查，重查后才允许 | 验证真实物理断线和重连场景，防止驱动保留最后一次值 |
| 重启HMI | 初始状态为禁止，不能自动恢复旧许可 | 验证内部对象初值、状态机初值和恢复锁存均为故障关闭 |
| 重启Windows电脑 | 网关自动启动、凭据保留、Boot ID变化、旧许可不恢复 | 同时验证部署、凭据存储、启动标识和HMI恢复策略 |
| 制造鉴权故障后恢复 | 原因93、许可0；修复后历史系统禁止审计补传 | 验证口令或令牌错误不会绕过许可，审计队列能在恢复后闭环 |

### 10.1 28项自动测试补足了什么

实机测试验证真实设备、驱动、网线和重启行为；自动测试用于稳定复现不适合在现场反复制造的边界条件。当前结果为28项通过、0失败，重点覆盖：

- 瓶号去空白、转大写、ASCII长度、16位边界和未使用字符填0，防止编码或残留字符查错瓶。
- Boot ID不匹配、重复序号、非零序号回绕、输入不完整和并发请求，防止旧响应、半包或请求竞争被放行。
- 日期缺失、非法、昨天、今天、明天、后天、闰日和跨年，验证“提前一天禁用”的边界没有偏差。
- 气瓶不存在、不唯一、停用、报废、丢失、非法状态以及多项日期同时失败，验证主档异常全部禁止且明细完整。
- 云端超时、401、HTTP异常、数据库失败、云端审计失败和内部异常，验证所有系统错误路径许可始终为0。
- 允许结果必须先有云端审计，本地审计写盘失败也不能放行，防止设备已允许而记录不可追溯。
- 同一 `request_id` 的补传幂等和响应字段最后提交 `response_seq`，防止重复审计和HMI读取半包响应。
- 实际Modbus FC03、FC06、FC16、TCP端口占用和同一应用停止再启动，验证单元逻辑与真实通讯驱动行为一致。

上述结果证明的是 HMI-网关-云端链路。正式工程接入 PLC 后，还必须继续完成 HMI-PLC 断线、PLC重启、PLC看门狗和原充装联锁的联合验收。

## 11. 正式HMI和PLC的最小接入要求

正式画面可以很简单，但内部至少需要保留：

```text
GatewayPermitOk              网关查询许可
HMI_FillPermitCmd            HMI写给PLC的许可位
HMI_FillPermitHeartbeat      HMI写给PLC的变化心跳
FillPermitFinal              PLC内部最终许可
```

建议数据关系：

```text
GatewayPermitOk
  AND HMI-PLC通讯正常
    → HMI_FillPermitCmd

GW05
    → HMI_FillPermitHeartbeat

HMI_FillPermitCmd
  AND PLC内3秒心跳有效
    → FillPermitFinal

原有全部充装条件
  AND FillPermitFinal
    → 进入原有充装流程
```

- PLC只能在正式充装流程中引用 `FillPermitFinal`，不得直接使用HMI原始写入位。
- `FillPermitFinal`只能作为原有条件的串联附加条件，不能并联绕过任何原安全条件。
- 正式HMI如果只显示一个“是否允许充装”标签，最好读取PLC的 `FillPermitFinal`；如果显示 `GatewayPermitOk`，标签名称应明确为“网关查询许可”。
- HMI-PLC通讯恢复后也不能自动恢复断线前的旧许可，必须重新查询当前瓶号。

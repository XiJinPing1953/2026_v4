# 会计与金额规则入口

销售、客户结算和导出统一遵循 [账务当前决定](../state/domains/accounting.md)。这里仅保留凭证专属约定，不另维护一套销售金额公式。尤其不能把“新建 m³ 销售默认走流量结算”用于批量判定旧单归属。

## 凭证约定

- 来源：销售创建/更新，来源键 `sale:<saleId>`。灌装只作运营记录，不直接生成凭证。
- 凭证默认草稿；已过账凭证不直接覆盖。计算金额采用权威账务模块，不能凭证侧再重算。
- `on_account` 只记应收；其他收款按实际方式映射科目。来源、收款、抹零或退款的业务含义不得在科目映射时改变。

| 科目 | 编码 |
|---|---|
| 应收账款 | 1122 |
| 主营业务收入 | 6001 |
| 库存现金 | 1001 |
| 银行存款 | 1002 |
| 微信 / 支付宝 / 支票 | 1002-WECHAT / 1002-ALIPAY / 1002-CHECK |

借方按真实收款账户和未收应收区分，贷方按权威应收来源记录。冲抵、退款、抹零、期初的对账口径及去重见领域决定；不以这张简表推导所有历史凭证。

来源：原会计文档与 [销售实现](../uniCloud-alipay/cloudfunctions/crm-sale/index.js)。2026-09-05 移除旧文档“收入沿用旧系统”及无结算模式的 m³ 通用公式，替代关系记录于领域文件。任何历史凭证修正单独给出预览与核对，不随代码规则归一自动执行。
